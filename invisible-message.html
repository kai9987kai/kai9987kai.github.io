Recovery limits: triple redundancy can correct one substitution per group of three coded symbols. It cannot reliably repair inserted or deleted characters, marker loss, truncation, or application-level removal of invisible Unicode.

Compact quaternary channel

Symbols U+200B, U+200C, U+200D and U+2060 encode two bits each, so every payload byte takes four symbols. The format is self-delimited using U+2063/U+2064 framing.

Authenticated cryptography

Passphrases derive AES-256-GCM keys using PBKDF2-HMAC-SHA256, 600,000 iterations and a fresh 128-bit salt. Each encryption uses a fresh 96-bit IV and a 128-bit tag.

Backward-compatible decoding

Original INV1 frames are decoded using the same 0/1 codepoints, U+200D byte delimiters, U+2060 frame delimiters and the four-byte length field.

Integrity and bounds checking

IUV2 adds CRC-32 to detect accidental payload corruption. It is not a cryptographic authentication mechanism; only AES-GCM provides authentication for encrypted data.

Redundancy experiment

Each quaternary character can be sent three times. Majority voting repairs a single substitution per triple, trading 3× size for limited recovery.

Local-first and inspectable

No external libraries, network calls, cookies, telemetry or stored passwords. The standalone HTML can run offline; encryption requires Web Crypto availability in the browser context.

Protocol + research references

INV1 uses MAGIC[4] + LENGTH_U32_BE + UTF8, with one 8-symbol byte separated by U+200D and framed by U+2060.

IUV2 uses MAGIC[4] + FLAGS[1] + LENGTH_U32_BE[4] + CRC32_BE[4] + DATA. DATA is UTF-8, or SALT[16] + IV[12] + AES-GCM ciphertext and tag. Triple repetition is indicated by a distinct frame-start marker and flag.

Flags: bit 0 = encrypted; bit 1 = triplicate symbols. CRC32 covers MAGIC, FLAGS, LENGTH and DATA. Maximum text secret: 128 KiB UTF-8.

Research: Unicode UTS #39, Unicode Security Mechanisms (18.0); Unicode UAX #15, Normalisation (18.0); MDN: AES-GCM IVs and authenticated data; MDN: Web Crypto KDF; OWASP: PBKDF2 cost guidance.

Security scope: steganography hides presentation, not the existence of data from forensic tools. Password-protected payloads use standard primitives, but this application/protocol has not undergone an independent security audit. Avoid sensitive reliance on it without expert review.
